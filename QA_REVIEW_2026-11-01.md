# Jeevan: integrated design and functional QA

Date: 1 November 2026. Three specialist agents and the main agent reviewed the shared interface, staff workflows, patient workflows and public pages. All test records were fictional. Changes remain local; no production deployment or real patient data was involved.

## Result

The tested clinic workflows pass after the repairs below. The application is ready for supervised acceptance testing on the intended host. This does not establish that every possible input, browser, outage or deployment configuration is correct.

## Repairs

- **Footer:** rebuilt the public footer with readable contrast, consistent columns, meaningful navigation, account/recovery links and a real clinic-contact destination. Removed the floating duplicate contact button. Hospital-profile footer links also have readable contrast. Desktop uses four columns; phones use one column without horizontal overflow.
- **Shared layout:** corrected the 992–1024px navigation breakpoint that made visible links inaccessible; prevented duplicate script initialization/table hints; small tables no longer inherit an unnecessary 800px width. Staff names wrap within phone headers. Patient-only hero styles are scoped to the patient dashboard.
- **Patient dashboards:** both dashboard URLs now use one canonical view. Upcoming totals exclude past accepted visits. Report/prescription totals are not capped by their five-item previews; historical prescriptions are labelled Saved rather than Active.
- **Patient profile:** corrected stale email/phone attributes across applicable templates; removed the fabricated three-notification alert; linked the bell to consent requests. The birth-date field now has the correct name, ISO value and accessible label. Validation errors are visible. Future birth dates, invalid phones and duplicate emails are rejected; text edits preserve unchanged photos and saves are atomic.
- **Account changes:** password changes apply Django password validators and return to a valid sign-in route rather than failing after the password was already changed.
- **Appointments:** malformed/nonexistent selections fail safely. Reading appointment lists no longer globally changes patients' statuses. Accepted visits remain available for completion after their scheduled time. Receptionist status changes require POST; malformed date/doctor filters are rejected.
- **Staff boundaries:** inactive coordinators cannot continue using old sessions; exports validate selected identifiers, consent and archive names. Nurse directories are hospital-scoped. Nurses/coordinators can still find registered patients after historical appointments expire. Unrelated patient filters do not disclose identity.
- **Medication information:** the legacy percentage now describes self-reported days logged, not prescribed doses taken. Missing eligible information is represented as missing, not perfect/zero adherence. This incomplete logging metric no longer contributes to the heuristic health score.
- **Homepage:** standalone login document/style leakage was removed in the earlier repair. Sections remain visible without scroll-triggered blank blocks, navigation handles empty fragments and missing optional elements safely, and unsupported vetting claims were removed.
